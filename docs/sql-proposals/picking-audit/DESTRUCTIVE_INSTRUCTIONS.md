# Instrucciones destructivas en las propuestas SQL

Inventario estático con pglast 7.22: se analiza SQL y cuerpos PL/pgSQL/SQL, sin ejecutar instrucciones. Los `CREATE FUNCTION` se inspeccionan; los cuerpos originales citados como datos en preflight no se ejecutan y no se cuentan como comandos.

**Sin UPDATE sin WHERE, sin DELETE sin WHERE y sin TRUNCATE ejecutables.** Los privilegios TRUNCATE de REVOKE/GRANT no son instrucciones TRUNCATE. `TG_OP=DELETE/UPDATE` en triggers compara texto, no elimina ni modifica filas. No hay SQL dinámico EXECUTE.

Las UPDATE existentes tienen WHERE por ID de pendiente, faltante, entrega, evento o lista explícita de nuevos IDs. No se actualizan ni concilian históricos en masa. El instalador ejecutaría esas UPDATE únicamente al invocar después una RPC autorizada; crear las funciones no ejecuta sus cuerpos.

La reversión restaura las ACL previas de la tabla histórica de diferencias, incluidas sus concesiones antiguas de DML. Es una restitución explícita al estado anterior, no un permiso nuevo para Recepción; si esa exposición no es aceptable, conservar el endurecimiento mediante una corrección forward revisada. Ninguna reversión ni concesión se ejecutó en Supabase.
